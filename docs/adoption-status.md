# 중앙 적용 현황

**2026-10-27 (Asia/Seoul)** 중앙 참조·자동 업데이트 후속 변경 기준입니다. 전체 채택 상태는 기존 기록을 유지합니다. 중앙에는 리포별 요약만 두고 상세 점검·실제 설치 버전·명령·리뷰는 각 리포의 `ADOPTION_CHECKLIST.md`, 기준·예외는 `STANDARDS.md`에서 확인합니다. [채택 지침](adoption.md)과 [판정 기준](checklist.md)을 따릅니다.

## 상태 기준

- **완료**: 적용 대상 필수 항목 PASS/N/A, 기본 브랜치 반영 및 해당 커밋 검증 확인.
- **예외 포함**: 기본 브랜치에 적용됐고 필수 TODO 없이 승인 예외가 남음.
- **진행 중**: 구현·검증·리뷰·체크리스트 마감 또는 병합이 남음.
- **미착수 / 적용 제외**: 전체 채택 미시작 또는 사용자 지정·보관·이전으로 대상에서 제외.

참조·배지·ZIP 같은 부분 변경의 성공은 전체 채택 완료를 뜻하지 않습니다. 과거 다른 커밋의 PASS를 최신 검증으로 재사용하지 않습니다. 실물·실서비스·HA UI 검증은 실제 HA 테스트와 별개입니다.

## HA 통합 리포

### 2026-10-27 current HA 자동 기대값 후속

담당 root / 독립 리뷰 review_pr36. 중앙 [PR #36](https://github.com/eigger/hass-repo-standards/pull/36)은 독립 리뷰 차단 지적 없이 squash `c8c2771a2de68769af40f56e19e958e374e6e091`로 병합했습니다. 해당 커밋의 [필수 CI 4개](https://github.com/eigger/hass-repo-standards/actions/runs/40413753268)와 [draft 준비](https://github.com/eigger/hass-repo-standards/actions/runs/40413976945)가 성공했고, 이번 세션의 명시적 사용자 승인으로 [immutable v1.1.3](https://github.com/eigger/hass-repo-standards/releases/tag/v1.1.3)을 발행했습니다. release metadata·내부 action SHA·관리자 preflight 및 발행 후 `verify-release`의 immutable/peeled SHA 확인을 완료했습니다. 로컬 Python 3.14.6/packaging 26.3/PyYAML 6.0.3/Ruff 0.17.1에서 UTF-8 `test_tools` 31개·Ruff check/format·actionlint 1.7.12·중앙 검사 통과. 초기 CRLF 템플릿 비교 실패는 중앙 snapshot을 LF로 읽어 재검증했으며 대상 파일을 우회하지 않았습니다. Windows 전체 suite는 플랫폼 오류 발생 후 중단했고 PASS로 기록하지 않습니다. 전체 회귀·실제 HA runtime 성공 근거는 해당 Linux CI입니다.

hass-ble-esl은 기본 브랜치 `5137b9d`에서 [후속 PR #277](https://github.com/eigger/hass-ble-esl/pull/277) 적용 중입니다. 중앙 v1.1.3 채택, current/editor의 고정 HA 기대값 제거, [#275](https://github.com/eigger/hass-ble-esl/pull/275)의 플러그인 0.13.373 갱신을 함께 검증합니다. 최소 HA 2025.12.0·최소 requirements/constraints·지원 메타데이터와 기존 전체 채택 상태·예외는 유지합니다. 다른 21개 리포의 참조는 기존 Dependabot daily PR·메타데이터 동기화·same-major 자동 머지 경로에 맡기며 이번 세션에서 일괄 수정하지 않습니다. updater는 고정 기대값을 제거하지 않으므로 해당 전환은 별도 부분 적용 대상입니다. 상세 후속 검증은 대상 ADOPTION_CHECKLIST와 적용 PR에 기록합니다.

3개 Standards 분리 후속은 각 PR head의 전체 CI 성공을 확인한 뒤 기본 브랜치에 스쿼시 머지했습니다. PR CI와 병합 커밋의 push CI는 별도 실행이며, 과거 전체 채택의 예외·미완료 항목은 유지합니다. 지원 최소·런타임·의존성·기존 테스트는 해당 작업에서 변경하지 않습니다.

## 다른 유형의 리포

HA 통합 전용 구조·테스트는 강제하지 않습니다. 아래 네 리포는 공통 문서·CI 범위 채택 기록이 없어 미착수로 유지합니다.

| 리포 / 기본 브랜치 | 적용 범위 | 상태 |
|---|---|---|
| [hass-imagespec-card](https://github.com/eigger/hass-imagespec-card) / `main` | 카드 문서·CI | 미착수 |
| [hassble-android](https://github.com/eigger/hassble-android) / `main` | Android 문서·CI | 미착수 |
| [hassble-config](https://github.com/eigger/hassble-config) / `main` | YAML 문서·CI | 미착수 |
| [hassio-apps](https://github.com/eigger/hassio-apps) / `master` | 앱 문서·CI | 미착수 |

## 로컬 checkout 참고

- `hass-coolled`는 `hass-ble-led-sign`과 같은 원격이므로 중복 집계하지 않습니다.
- `hass-timemore`는 초기 GitHub 목록에 없으며 원격 존재·접근 확인 전 상태를 단정하지 않습니다.
- 중앙 `hass-repo-standards` 자체는 HA 통합 적용 실적에 포함하지 않습니다.

## 갱신 절차

1. 시작·종료·차단·범위 변경 등 의미 있는 상태 변화에 최신 중앙 main의 해당 행만 갱신합니다.
2. 대상 커밋·기준 release/SHA·담당자와 상세 체크리스트·CI 링크를 연결하고, 필수 TODO·예외·미검증을 남깁니다.
3. 로컬 작업·열린 PR·미실행/실패를 완료로 기록하지 않습니다. 게시할 수 없으면 미반영 상태와 이유를 보고합니다.
4. 사용자 승인 없이 다른 리포의 적용 범위·지원 최소·예외를 변경하지 않습니다. 상세 규칙은 GOV-04를 따릅니다.

## 이전 기록

중복된 ZIP·배지·워크플로·참조 전환 작업 일지는 [정리 전 원문](https://github.com/eigger/hass-repo-standards/blob/f8cb119260a3fed50648c9a42844f8f0b93b1866/docs/adoption-status.md)에 보존했습니다. 당시 표준 SHA·채택 커밋·PR·실제 버전·검증 결과·담당자·제약을 확인할 수 있습니다. 과거 기록을 현재 결과로 재판정하지 않습니다. 이번 정리는 현황·안내 문서의 중복 제거이며 규칙 ID·필수/권장 수준·검증 의무는 변경하지 않습니다.
