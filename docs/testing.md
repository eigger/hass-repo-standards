# 테스트와 호환성 규칙

**TEST-01 필수**: 버그 수정은 재현되는 회귀 테스트를 추가합니다. 프로토콜 parsing, 잘못된 데이터, timeout, disconnect, 중복 설정, unload/cleanup 등 사용자 동작을 검증합니다. 단순 문구 수정에 구현을 복제한 테스트를 만들지 않습니다.

**TEST-02 필수**: 테스트 profile을 `unit`과 `ha`로 구분합니다. stub/mock만으로 통과한 테스트를 HA 호환성 테스트라고 부르지 않습니다. CI summary에 실제 설치 HA 버전을 출력합니다. Python matrix가 넓다는 이유만으로 HA 최소 버전 검증을 대체하지 않습니다.

**TEST-03 필수**: `ha` profile은 실제 HA와 호환되는 pytest 플러그인/fixture를 사용합니다. Python 버전은 해당 HA의 Requires-Python을 만족해야 합니다. 플러그인이 HA 버전을 고정하는 경우 제약을 존중합니다. 조합을 억지로 해결하기 위한 무분별한 `--no-deps`는 금지합니다.

**TEST-04 필수**: 최소 HA를 지원한다고 선언하면 별도 환경에서 그 **정확한 버전**을 테스트합니다. `homeassistant>=최소버전`은 최소 버전 테스트가 아닙니다. 미검증 기존 리포는 예외와 보완 계획을 기록합니다. 테스트할 수 없는 버전을 기계적으로 지원 범위에서 삭제하지 않습니다.

**TEST-05 필수**: 최소 라이브러리와 선택된 현재 라이브러리 환경을 구분합니다. `>=`만 pip 설치하면 보통 최신이 선택됩니다. 공통 `dependency-mode: minimum`은 명시한 패키지를 하한 버전에 고정하고 실제 설치 버전을 검증합니다. 이 환경은 테스트 라이브러리의 다른 요구사항과 함께 resolver를 통과해야 합니다.

**TEST-06 필수**: 기본 CI는 실물 BLE 장치·개인 계정·인터넷 API에 의존하지 않습니다. 네트워크와 전송은 경계에서 대체하고 HA 생명주기는 실제 fixture로 검증합니다. 실물 검증은 별도 수동 절차와 기기/펌웨어/환경을 기록합니다.

**TEST-07 권장**: config flow의 성공·실패·중복·재인증, entry migration, unavailable 복구와 task 취소를 우선합니다. coverage는 숫자 채우기보다 누락된 사용자 경로를 찾는 용도로 사용합니다.

공통 Python workflow 입력 `test-profile`은 환경을 확인하고 summary에 기록합니다. `ha`이면 HA가 실제 설치되어야 하며, `expected-ha-version`을 주면 해당 버전과 정확히 일치하는지 확인합니다. 실제 HA를 호출하는 테스트 작성 자체는 각 리포 책임입니다.
